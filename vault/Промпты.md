# Промпты и гарантия формы JSON

> Состояние (2026-10-15): **дизайн, не реализовано.** Инференс на candle уже работает
> (`infer.rs`), но промпт-обвязка под интенты и парсер вывода ещё НЕ написаны.
> GBNF (llama.cpp) отброшен вместе с llama.cpp — см. [[ADR-0002-llm-gbnf]].

Цель: маленькая и «глупая» модель должна **не думать**, а извлечь из промпта заранее
приготовленную команду, подходящую запросу.

## Системный промпт (компактный)
- Список известных интентов (id + краткое описание + примеры) — сжато.
- **Параметры каждого интента** (`params`: имена/типы/обязательность) — из манифеста. Модель
  предупреждена: для запуска нужны **все обязательные** данные. См. [[#Дозапрос данных (slot-filling)]].
- Строка профиля предпочтений: `Known user preferences: name=…; language=ru; …`
  (всегда, из `profile.json`, см. [[ADR/0006-память-предпочтения]]).
- Несколько few-shot пар «фраза → JSON».
- Жёсткая инструкция: вернуть **только** JSON.

## Формат вывода
```json
{ "intent": "set_timer", "params": { "duration_seconds": 300 }, "reply": "Таймер на 5 минут" }
```
или
```json
{ "intent": "unknown", "params": {}, "reply": "" }
```

## Гарантия формы вывода (вместо GBNF)
- Прежний механизм — GBNF-грамматика llama.cpp — **отброшен** (нет в candle).
- Кандидаты: промпт + строгий парсер + retry; ручной constrained-decoding
  (маска логитов по маленькому автомату); `llguidance` поверх candle.
- **Решение не принято** — следующий шаг этапа 4. См. [[ADR-0002-llm-gbnf]],
  [[Открытые-вопросы]].
- Слоты валидируются повторно в `skills` (типы/диапазоны) — см. [[Навыки]].

## Дозапрос данных (slot-filling)

- Если в реплике **не хватает обязательных** параметров интента — модель **не отказывает**, а
  задаёт **уточняющий вопрос** («На сколько минут?»).
- Если навык умеет **читать** кандидатов (`read`-метод) — вопрос конкретизируется списком.
- Ответ пользователя продолжает **ту же сессию**; частично заполненный вызов хранится в сессии.
- Реплика, **не являющаяся ответом** на вопрос (подтверждение/уточнение), **не** трактуется как
  ответ — сессия **выходит в новый навык** (см. [[ADR-0012-диалог-контекст-выход-чтение]]).
- Когда все обязательные данные собраны — отдаём исполнение навыку.
- См. [[ADR-0011-сессия-и-подтверждение]], [[Навыки#Дозапрос данных (slot-filling)]].

## Контекст
- В промпт — компактная выжимка последних `K` ходов (см. [[Контекст-и-память]]).
- История включает результат действия (и **`id` от ОС**, если она его дала) — `A: set_timer → ok, id=7` —
  чтобы модель разрешала ссылки «удали **его**», «**ещё раз**» (см. [[ADR-0012-диалог-контекст-выход-чтение]]).
- Плюс всегда строка профиля предпочтений (переживает выпадение из окна).
- Каталог интентов и few-shot держим короткими ради экономии окна.

## Локализация
- Промпт/примеры — RU (и EN при необходимости). Язык интерфейса не влияет на грамматику.

## Параметры сэмплинга
- temperature низкая/0; детерминизм важнее «творчества».
- `n_ctx` минимальный, чтобы KV-кэш был маленьким. См. [[Автономность]].
