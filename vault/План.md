# Glas — ассистент управления телефоном (Sailfish OS)

Голосовой ИИ-ассистент для Sailfish OS: распознаёт речь, извлекает команду («навык»),
выполняет её и отчитывается. Работает **локально**, в фоне, при минимальном потреблении.

## Ключевые решения (зафиксировано)
- **Имя:** Glas. Репозиторий проекта: `boshtannik/glas` (корень — `glas/`).
- **Стек:** Rust + QML/Silica, один процесс. Вендоренные `qmetaobject-sfos-rs` + `sailors`
  из референса. См. [[ADR/0001-стек]].
- **STT:** whisper.cpp (`whisper-cli`, патч `--audio-ctx`). **TTS:** piper.
  Запись — `parecord`, воспроизведение — QML `MediaPlayer` (легаси-`cpal`/`hound` в
  `src/audio/` не используется; см. [[ADR-0001-стек]]).
- **Интенты:** **candle (чистый Rust), GGUF on-device** (llama.cpp отброшен — CMake висел под
  sb2; см. обновление [[ADR/0002-llm-gbnf]]). Генерация резидентна, выгрузка по простою.
  Вывод — строго `{intent, params, reply} | unknown`; **механизм гарантии формы JSON
  пересматривается** (у candle нет GBNF). См. [[Промпты]].
- **Навыки:** **декларативно, без произвольного кода** (см. [[ADR-0007-исполнение-навыков]]).
  Единый трейт `Skill` (`manifest`/`validate`/`execute`); `BuiltinSkill` (Rust) +
  `DeclarativeSkill` (данные: `dbus`/`open`/композиция builtin). Пользовательские навыки = файл/
  папка/URL, без перекомпиляции. Шаринг — рецепты/алиасы (`.gskill`), не скрипты.
  См. [[Навыки]], [[Безопасность]].
- **Контекст:** только скользящее окно + честное UX-напоминание об ограниченной памяти.
  См. [[ADR/0003-контекст-окно]], [[Контекст-и-память]].
- **Страницы:** Диалог (крупный микрофон) · Настройки · Голосовые модели · Навыки;
  обложка — быстрый микрофон. См. [[UI-Страницы]].
- **Первый запуск:** если настройки/модели не заданы — первым делом ведём на [[Настройки]]
  (см. [[Флоу-UI]]).
- **Термин:** единый — **«навык»** (не «команда»).
- **Ход:** стартует **на отпускании** кнопки push-to-talk. См. [[Флоу-UI]].
- **Шэринг навыков:** файл `.gskill` (имя, команда, метаданные, версия совместимости),
  импорт из файла или по URL. См. [[Шаблоны-команд]].
- **Фон/автономность:** пока ничего не требуется — «ест почти ничего». См. [[Автономность]].
- **Сборка:** Docker `sailo-rs` + `mb2` на ПК. Поток: `git push` здесь → `git pull` на ПК →
  build → RPM `harbour-glas`. См. [[Сборка]].

## Референс
`https://github.com/boshtannik/mason` — native opencode client (`harbour-opencode`), Rust+QML.
Оттуда берём: мост Rust↔QML, аудио (cpal/hound/whisper/piper), каталог моделей,
RPM-обвязку, `mbuild.sh`. См. [[Архитектура]].

## Пересмотр архитектуры (2026-10-16)

Согласованное направление (в коде ещё не реализовано, кроме отмеченного). Полностью — в
[[Архитектура#Целевая архитектура (обсуждено 2026-10-16)]].

- **Ядро:** **один worker + единая очередь событий**; автомат хода
  `Idle→Recording→Transcribing→Thinking→[AwaitingConfirmation]→Executing→Speaking→Idle`.
  См. [[ADR-0008-ядро-worker-очередь]].
- **Протокол:** исчерпывающие `enum Command`/`enum Event` + константы (правила владельца из
  opencode: без `Unknown`/`_ =>`, `warn` на нереализованное, ключи/маркеры — в константах,
  логи только на английском).
- **Модельный слой:** автономный крейт `glas-models` (без Qt, тестируется на хосте), `candle`
  за трейтом-бэкендом. См. [[ADR-0009-модельный-слой]].
- **Память:** только поставщик контекста (предпочтения + скользящее окно), трейт с запасом
  на рост. См. [[Контекст-и-память]].
- **Навыки:** декларативно, без произвольного кода; один трейт `Skill`; реестр — единый
  источник для промпта/валидации/исполнения. См. [[ADR-0007-исполнение-навыков]], [[Навыки]].
- **Примитивы — через ОС, не через железо:** только стабильные интерфейсы ОС (D-Bus-сервисы
  Sailfish, штатные утилиты); полный инвентарь доступного снят разведкой 2026-10-16 —
  [[Возможности-ОС]]. Что войдёт в примитивы — решается на этапе разработки (Jack). См.
  [[ADR-0010-примитивы-через-ОС]].
- **Диалог:** сессия хода как первоклассная сущность (индекс `session_id → skill_id`, уборка
  состояния навыка), **сужение ввода при подтверждении** (в `AwaitingConfirmation` принимается
  только «да/нет»), выключенный навык **не исполняется** даже при пришедшем интенте, явный
  **статус ресурса** LLM/STT. Заимствовано у Snipek. См. [[ADR-0011-сессия-и-подтверждение]],
  [[Исследование-загнувшихся-проектов]].
- **Диалог: контекст, ссылки, выход, чтение:** сессия ≠ контекст (закрытие сессии не стирает окно;
  ссылки «удали его» — по контексту, с `id` результата в строке, если ОС его дала); **не-ответ в
  ожидании → выход в новый навык**; **перебивание = повторное нажатие PTT**; **чтение —
  дополнительный метод навыка** (`read`, не отдельная сущность) для конкретных уточняющих вопросов
  (списки). См. [[ADR-0012-диалог-контекст-выход-чтение]].
- **Пайплайн** «STT → интент → безопасность → навык → TTS» — стержень, вокруг которого
  крепятся остальные решения (обсуждается дальше).
- **Отложено на обсуждение:** как наполняется профиль предпочтений; механика скользящего окна;
  гарантия формы JSON ([[Промпты]], [[ADR-0002-llm-gbnf]]).
