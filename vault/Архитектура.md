# Архитектура

> Состояние: сверено с кодом 2026-10-15. **Целевая схема (обсуждено 2026-10-16)** —
> ниже в разделе [[#Целевая архитектура (обсуждено 2026-10-16)]]; ADR-0007/0008/0009.

Один процесс: Rust-бинарь запускает QML-движок (через `sailors`/`sailfishapp`),
регистрирует `AppBridge` как QObject и отдаёт корневой QML. Как в референсе mason.

## Слои
```
QML (Silica UI)
  │  qt_property! / qt_method! / qt_signal!   (qmetaobject-rs)
  ▼
AppBridge (bridge/app.rs)          ← всё в главном (QML) потоке
  │  длительные операции уходят в фоновые потоки,
  │  результат возвращается через mpsc-канал; QML опрашивает poll()/status_json()
  ▼
Фоновые потоки (std::thread, без tokio/воркера)
  ├── voice      — parecord (PTT) + whisper-cli (STT) + piper (TTS) + VoiceStore
  ├── llm        — каталог/скачивание моделей (HF, curl), LlmStore
  ├── infer      — candle: резидентная модель + watchdog выгрузки по простою
  └── memory     — glas-memory (profile.json, отдельный крейт)
```

**Важно:** отдельного «воркера» с очередью `Cmd` нет. `AppBridge` живёт в QML-потоке;
каждая длительная операция (распознавание, генерация, скачивание) стартует свой
`std::thread` и возвращает результат через `std::sync::mpsc`. QML периодически зовёт
`bridge.poll()` (таймер 250 мс на странице диалога) и `*_status_json()` на страницах
моделей (таймер 400 мс). Раньше планировался worker-поток + `Arc<Mutex<..>>` (как в
референсе) — от него отказались в пользу этой схемы.

## Поток обработки одного запроса (реализовано: STT → TTS)
```
удержание mic (onPressed) → parecord → WAV 16k mono s16
  → отпускание (onReleased) → ptt_stop → поток: whisper-cli → текст
  → poll() забирает текст → bridge.answer → UI
  → кнопка-динамик → tts_speak → поток: piper → WAV в кэш → tts_file
  → QML MediaPlayer проигрывает WAV
```
**Ещё не реализовано:** интент → навык → выполнение (см. [[Навыки]]); VAD-автостоп;
лента бабблов. Инференс LLM есть (`llm_generate`/`llm_test` + тест-форма в
`ModelCardPage`), но он не связан с STT в сквозной пайплайн.

## Модули и ответственность
- **bridge** — единственная точка Rust↔QML. Держит `VoiceStore`, `LlmStore`, `Recorder`,
  `Memory`, `Settings`; пер-операционные `mpsc::Receiver` для фоновых результатов.
- **voice** (`voice.rs`) — PTT через `parecord`; STT через `whisper-cli` с патчем
  `--audio-ctx` (сокращает окно с 30 с до длины клипа); TTS через `piper` с дисковым
  кэшем WAV (лимит 200 файлов / 200 МБ, LRU); `VoiceStore` — общий с opencode каталог
  STT/TTS.
- **llm** (`llm.rs`) — каталог «thinking»-моделей: живой Hugging Face API, `LlmStore`
  (поиск/пагинация/скачивание/выбор), расчёт влезаемости.
- **infer** (`infer.rs`) — candle-инференс одной активной GGUF-модели. Модель резидентна
  (static `OnceLock<Mutex<Option<Loaded>>>`), выгружается watchdog-потоком по
  `idle_unload_secs`. Диспатч по `general.architecture`.
- **memory** (`glas-memory`) — долговременная память (профиль предпочтений, `profile.json`).
  См. [[ADR-0006-память-предпочтения]], [[Контекст-и-память]].
- **settings** (`settings.rs`) — `~/.config/harbour-glas/settings.json`.
- **audio** (`src/audio/`) — ЛЕГАСИ-скелет из референса, собирается только с фичей `voice`
  (cpal/hound); реальный PTT идёт через `voice.rs`, а не отсюда.

## Протокол (два слоя)
1. **`enum Cmd` (`cmd.rs`)** — задел «единого источника» имён команд
   (`#[serde(tag = "cmd", rename_all = "snake_case")]`). Сейчас почти не используется.
   Варианты: `Listen`, `Stop`, `Cancel`, `Undo { id }`, `SkillList`, `SkillEnable { id, on }`,
   `SkillImportUrl { url }`, `GetSettings`, `MemoryList`, `MemorySet { key, value }`,
   `MemoryForget { key }`.
2. **Фактический протокол** — типизированные qt_method'ы `AppBridge` + строковые store-команды:
   - `voice_command(cmd, val)`: `voice_select_stt`, `voice_select_tts`, `voice_lang`,
     `voice_download`, `voice_download_cancel`, `voice_delete`, `voice_catalog_update`.
   - `llm_command(cmd, val)`: `llm_select`, `llm_search`, `llm_page_active`, `llm_load_more`,
     `llm_catalog_update`, `llm_download`, `llm_download_cancel`, `llm_delete`.
   - методы: `ptt_start`/`ptt_stop`, `tts_speak`/`tts_stop`, `poll`, `cancel`,
     `voice_status_json`, `llm_status_json`, `llm_model_json`, `llm_available`,
     `llm_generate`/`llm_test`, `memory_facts`/`memory_set`/`memory_forget`/`memory_prompt_line`.

## Вендор из референса
`vendor/qmetaobject-sfos-rs` — форк qmetaobject-rs под Sailfish; `vendor/sailors` —
обёртка `SailfishApp`. Оставляем как есть. См. [[ADR/0001-стек]], [[Сборка]].

> **Сделано (2026-10-17):** крейт `glas-core` (Qt-free, host-тесты) — `Command`/`Event`
> (исчерпывающие), автомат хода, `SkillRegistry` + builtin-навыки, сессии
> (`SessionStarted`/`SessionEnded`), `MemorySet`/`MemoryForget`, трейты движков с фейками,

### Каркас: один worker + единая очередь событий

```
QML (UI) ─┐
таймеры  ─┤
STT-поток ┤   ┌──────────────────────────────┐
infer-пот ─┼──▶│   ОДНА ОЧЕРЕДЬ СОБЫТИЙ  mpsc<Event> │
download ─┤   └───────────────┬──────────────┘
D-Bus    ─┘                   ▼
                 ┌──────────────────────────────┐
                 │  WORKER (1 поток):            │
                 │  event-loop + автомат «хода»  │
                 │  весь match — в одном месте   │
                 └───────────────┬──────────────┘
                                 │
      ┌───────────┬──────────────┼───────────┬───────────┐
      ▼           ▼              ▼           ▼           ▼
   models      memory         skills      intent      stores
   (крейт)     (крейт)        (крейт)   (промпт+     (settings,
                                        парсер)      история)
```

- Все события (команды UI, результаты STT/LLM/скачивания, таймеры) идут в **одну** очередь;
  worker — единственная точка логики (как `dispatcher.rs` в opencode). См. [[ADR-0008-ядро-worker-очередь]].
- QML только рисует и шлёт команды; один вход/выход.

### Автомат хода (turn)

```
Idle → Recording → Transcribing → Thinking → [AwaitingConfirmation] → Executing → Speaking → Idle
```

| # | Стадия | Кто | Вход → Выход |
|---|---|---|---|
| 1 | Recording | UI + `parecord` | `Command::CaptureStart/Stop` → WAV |
| 2 | Transcribing | `whisper-cli` | WAV → `Event::Transcribed{text}` |
| 3 | Thinking (сборка промпта) | `intent` (builder) | текст → промпт = `system + memory + utterance` |
| 4 | Thinking (инференс) | `models` (candle за трейтом) | промпт → сырой вывод (событие слоя I/O) |
| 5 | Парсинг+валидация | `intent` + `SkillRegistry` | raw → `IntentCall{intent,params,reply}` / `Unknown` |
| 6 | Безопасность | policy из манифеста | `Event::NeedsConfirmation{...}` |
| 7 | Подтверждение | UI | `Command::Confirm{approved}` |
| 8 | Executing | `skills` | → `Event::ActionResult{ok,detail}` |
| 9 | Speaking | `piper` + UI | аудио готово (событие слоя I/O) → `Event::TurnDone` |

**Сборка промпта (шаг 3)** — узел, где встречаются три блока:

```
[system]  ← статика + КАТАЛОГ ИНТЕНТОВ (из SkillRegistry) + формат вывода + примеры
[memory]  ← модуль памяти: строка предпочтений + скользящее окно
[user]    ← текущая реплика
```

«Какие команды писать модели» берётся **из `SkillRegistry`**, а не из памяти: реестр —
единый источник для промпта, валидации и исполнения. См. [[Навыки]].

### Сессия хода и подтверждение

Многошаговый ход держит **сессию**: у активного хода есть `SessionId`, а в ядре — индекс
`session_id → skill_id` («кто держит сессию»). Пока сессия открыта, следующая реплика идёт
**тому же навыку**; состояние навыка чистится по `SessionEnded`/сбросу. В состоянии
`AwaitingConfirmation` ввод **сужается** — принимается только ответ «да/нет» (голосом или кнопкой
UI); **не-ответ не залипает, а выходит в новый навык** (реплика резолвится заново). Выключенный
навык **не исполняется**, даже если его интент пришёл.
Тяжёлые ресурсы (LLM/STT) имеют явный **статус** (`NotLoaded/Loading/Ready/Unloading/Error`).
См. [[ADR-0011-сессия-и-подтверждение]], [[ADR-0012-диалог-контекст-выход-чтение]].

### Протокол

Исчерпывающие enum'ы + константы (правила владельца из opencode): `Command` (UI → ядро)
и `Event` (ядро → UI); без `Unknown`/`_ =>`; `log::warn!` на нереализованные ветки; ключи/
маркеры — в константах; логи только на английском. См. [[ADR-0008-ядро-worker-очередь]].

### Модельный слой — отдельный крейт

`glas-models` (без Qt/sb2, тестируется на хосте) — каталог + скачивание + загрузка +
инференс; `candle` за трейтом-бэкендом. См. [[ADR-0009-модельный-слой]].

### Память

Модуль памяти — **только поставщик контекста** (предпочтения + скользящее окно), без сжатия
и ранжирования. Заложен **трейт с запасом на рост** (будущие `compact`/`rank`/summary —
как методы с дефолтными реализациями). См. [[Контекст-и-память]], [[ADR-0006-память-предпочтения]].

```rust
trait Memory {
    fn system_line(&self) -> String;
    fn window(&self) -> Vec<Turn>;
    fn record(&mut self, turn: Turn);
    fn set(&mut self, key: &str, value: &str) -> Result<(), MemoryError>;
    fn forget(&mut self, key: &str) -> Result<(), MemoryError>;
}
```

### Навыки

`SkillRegistry` с `Box<dyn Skill>`; `BuiltinSkill` (Rust) и `DeclarativeSkill` (данные:
`dbus`/`open`/композиция builtin). Никакого произвольного кода. См. [[ADR-0007-исполнение-навыков]],
[[Навыки]].

### С чего рисовать потоки сейчас (факт)

Текущая реализация (см. начало документа) — ad-hoc потоки + три `mpsc` + опрос. Целевая —
один worker + одна очередь. Разница осознанная; рефактор `AppBridge` — отдельная задача.
