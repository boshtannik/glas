# Контекст и память

> Состояние (2026-10-15): **профиль предпочтений реализован** (крейт `glas-memory`,
> `profile.json`, страница Memory, методы моста `memory_*`). **Диалоговое скользящее
> окно ещё НЕ реализовано** (нет интент-пайплайна). Числовые лимиты окна уже лежат в
> `Settings` (`max_turns`, `max_tokens`), но пока не используются.

Память делится на две независимые части (см. [[ADR/0006-память-предпочтения]]):
**диалоговую** (скользящее окно) и **долговременную** (профиль предпочтений).

## Диалоговая память — скользящее окно
- В промпт LLM уходит **последние `K` ходов** в компактном виде.
- Старые ходы выпадают и в контекст **не возвращаются** (в ленте UI остаются видимы).
- Отдельной «очистки» нет (при необходимости позже добавим «Новый диалог»).

## Формат контекста для модели
Только пары «реплика» + «разрешённое действие», без сырого stdout и полного текста ответа:
```
U: поставь таймер на 5 минут
A: set_timer {duration:300} → ok, id=7
U: а теперь на 10
```
Компактная форма нужна, чтобы «маленькая и глупая» модель не тонула в контексте
и не галлюцинировала.

### Ссылки («его/это/ещё раз») из контекста
- Закрытие **сессии** окно **не стирает** — ссылки разрешаются по контексту (см.
  [[ADR-0012-диалог-контекст-выход-чтение]]).
- В строку результата пишется **`id` от ОС**, если она его дала (напр. cookie `timed`):
  `A: set_timer → ok, id=7`. Это **не память объектов** — просто текст в строке контекста.
- «удали **его**», «удали **это**», «повтори», «**ещё раз**» резолвятся по последнему действию;
  если `id` есть — ссылка точная, иначе модель опирается на текст хода и/или навык читает (`read`).

## Бюджет
- Окно модели — маленькое (целимся в ~2048, максимум 4096 токенов).
- На историю резервируем ~600–800 токенов; каталог навыков — компактный.
- При превышении бюджета — **скользящее окно** (отбрасываем самые старые ходы).
  См. [[ADR/0003-контекст-окно]].

## Параметры (черновые)
- `max_turns` — предельное число ходов (напр. 8).
- `max_tokens` — предельный размер истории (напр. 700).
- Обрезка — детерминированная (без обращения к LLM).

## Профиль предпочтений — долговременная память
Маленькое хранилище фактов (`profile.json`), которое **всегда вставляется в system-prompt**.
Так предпочтения переживают выпадение реплики из окна.
- Формат: `facts: { key: { value, updated, source } }` (см. [[ADR/0006-память-предпочтения]]).
- В промпт — плоский список: `Known user preferences: name=…; language=ru; time_format=24h; …`.
- Реальные лимиты (`glas-memory`): `MAX_FACTS=64`, ключ ≤48 символов (`a-z0-9_.`),
  значение ≤200 символов, строка промпта ≤1600 символов (~400 токенов).
- Запись — через страницу Memory (`bridge.memory_set`), т.е. явным действием пользователя
  в UI (пока нет отдельного навыка `memory.set`; модель сама не пишет).
- Страница «Память»: посмотреть / добавить / удалить факты (правки существующих нет).
- Предпочтения **никогда не суммаризуются**.

## Компактификация хвоста (опционально, позже)
При переполнении окна выпадающие старые ходы **один раз** сжимаются в короткую
rolling-summary (редкий фоновый инференс). Не перессказываем всю историю каждый ход.

## UX-напоминание об ограниченной памяти
Пользователь должен понимать, что память конечна:
- Строка в ленте при выпадении хода: «🧠 Память ограничена: более раннее забыто.»
- Разовая заметка при первом запуске про природу ИИ и лимит слов.

## Хранение
- Профиль предпочтений — `~/.local/share/harbour-glas/profile.json` (реализовано).
- Полная история (со всеми бабблами и результатами) — SQLite (НЕ реализовано).
- Для промпта собирается выжимка «на лету» из последних `K` ходов (НЕ реализовано).
- rolling-summary (если включим) — рядом со историей, привязана к «хвосту» диалога.
