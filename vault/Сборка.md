## Модель работы
Разработка ведётся **здесь (на телефоне, через opencode = mason)**. Сборка — на ПК,
где развёрнут Docker-образ сборки. Поток:
```
здесь: git commit + git push
ПК:    git pull
ПК:    ./mbuild.sh  (Docker sailo-rs + mb2)  → harbour-glas-*.aarch64.rpm
телефон: установка RPM / deploy бинаря
```
SSH-креды и доступ к билд-машине — от пользователя (позже).

## mbuild.sh (как есть)
- `docker run` образа `registry.gitlab.com/whisperfish/sailo-rs/rust-aarch64-5.1.0.11:sfos-5-1`.
- Монтирует исходники (`:ro`) и **постоянный кэш** `~/.cache/glas-sailfish/cache`
  в `/home/mersdk/cargo-cache` (переживает перезапуски контейнера).
- `CARGO_HOME=/home/mersdk/cargo-cache/cargo-home` — вынесенный кэш реестра cargo
  (скачивание крейтов не повторяется при пересборках).
- Внутри: клонирует/кэширует `whisper.cpp` v1.5.4 и готовый `piper_linux_aarch64`,
  накладывает патч `--audio-ctx`, запускает `mb2 ... build`, кладёт RPM в `out/` и
  копирует в корень проекта.
- `--release` переключает режим; иначе debug.

## rpm/harbour-glas.spec — режимы сборки
```
release:  RUSTFLAGS="-Clink-arg=-Wl,-z,relro,-z,now -Ccodegen-units=1 -Clink-arg=-rdynamic"
debug:    RUSTFLAGS="... -Clink-arg=-rdynamic -Copt-level=1"   # ← важен opt-level=1
```
- **Зачем `-Copt-level=1` в debug:** `gemm-common` из `candle` содержит aarch64-fp16
  ассемблер-функции с `#[inline]` без `#[target_feature(enable="fp16")]`. При
  `opt-level=0` они эмитятся отдельно → LLVM `error: instruction requires: fullfp16`;
  при `opt-level>=1` инлайнятся и ошибки нет. (Глобальный `+fp16` использовать нельзя —
  ломает `candle-core` E0658 `stdarch_neon_f16`.)
- `%global __strip /bin/true`, `debug_package %{nil}` — чтобы не strip'ать вложенные
  движки (как в референсе).
- Движки: `whisper-cli` (из `third_party/whisper.cpp`, симлинк на кэш) и `piper` — в
  `%{_libexecdir}/%{name}/`; `assets/models.json`, иконки 4 размеров, `.desktop`.
- `%check` проверяет наличие символа `main`.

## Что адаптируем для Glas
- Имя проекта `glas`, пакет `harbour-glas`, спека `rpm/harbour-glas.spec`.
- Движки: `whisper-cli` (патч `--audio-ctx`) и `piper` (готовый aarch64-билд в кэше).

## Payload в /home, лаунчер — в /usr/bin (2026-10-17, важно)

Корневой раздел `/` маленький (~4.7 ГБ), поэтому тяжёлые хелперы (`whisper-cli`, `piper`)
перенесены в `/home` (большой LUKS-раздел), а в `/usr` остался **симлинк**
`/usr/libexec/harbour-glas` → `/home/harbour-glas`. Приложение зовёт хелперы абсолютными
путями `/usr/libexec/harbour-glas/...` (`voice.rs`) — резолвятся через симлинк.

**GUI-лаунчер `harbour-glas` ОБЯЗАН оставаться реальным файлом в `/usr/bin`.** Причина:
`libsailfishapp` (`SailfishAppPriv::dataDir()`) выводит каталог данных (QML, переводы) из
каталога исполняемого файла — берёт `exe.absolutePath()`, заменяет последний компонент на
`share/` и приклеивает имя приложения. Если `/usr/bin/harbour-glas` — симлинк, exe
резолвится в `/home/harbour-glas/...` → dataDir = `/home/share/harbour-glas` → главный QML
не найден → **белый экран** (без внятной ошибки). Лаунчер запускает по bare
`Exec=harbour-glas`, так что реальный файл в `/usr/bin` обязателен.

Итог раскладки:
- `/usr/bin/harbour-glas` — реальный GUI-бинарник.
- `/usr/libexec/harbour-glas` — симлинк на `/home/harbour-glas`.
- `/home/harbour-glas/{whisper-cli,piper/}` — тяжёлые хелперы.
- `/usr/share/harbour-glas/{qml,models.json}` — как раньше.

**Переход со старой раскладки** (in-place `rpm -Uvh` падает на `cpio: File from package
already exists as a directory in system`, т.к. каталог→симлинк):
1. `pkill -x harbour-glas`;
2. `devel-su rpm -e --nodeps harbour-glas`;
3. `devel-su rm -rf /usr/libexec/harbour-glas /usr/share/harbour-glas /home/harbour-glas /usr/bin/harbour-glas`;
4. `devel-su rpm -Uvh harbour-glas-*.rpm`.
Дальнейшие обновления (симлинк→симлинк) обычным `rpm -Uvh` проходят нормально.

См. `rpm/harbour-glas.spec` (`%define payloaddir /home/%{name}`). То же решение — в
harbour-opencode (`FIXES.md`, «Тяжёлый payload → /home»).
