# Навыки (команды)

«Навык» = манифест + реализация действия. Пользователь может включать/выключать,
создавать свои и делиться ими (см. [[Шаблоны-команд]]).

## Манифест
```json
{
  "schema": 1,
  "id": "set_timer",
  "name": "Таймер",
  "description": "Поставить таймер на N минут",
  "examples": ["поставь таймер на 5 минут", "таймер 10 мин"],
  "kind": "script",              // script | dbus | qml
  "params": {
    "duration_seconds": { "type": "int", "required": true, "min": 1 }
  },
  "exec": {
    "script": "set_timer.sh",     // для kind=script
    "dbus": { "bus": "session", "dest": "...", "path": "...", "iface": "...", "method": "..." }
  },
  "undo": "cancel_timer.sh",
  "danger": false
}
```

## kind — способ исполнения
- **script** — дочерний процесс (`sh`), аргументы передаются как **argv/env**, не строкой.
  Есть таймаут и kill. Для исходящих SMS/звонков и прочего «мощного» через DBus/sqlite.
- **dbus** — декларативный вызов D-Bus (таймеры `timed`, mce/громкость/фонарь и т.п.).
- **qml** — действие, выполняемое QML-стороной (напр., открыть приложение через `invoker`).

## Валидация слотов
- Типы из `params` (`int`, `float`, `bool`, `enum`, `string`), диапазоны, обязательность.
- Неизвестный интент/невалидные слоты → навык НЕ запускается, ассистент честно говорит
  «не понял/не хватает данных».

## Примеры для MVP
- **Таймер/будильник** — D-Bus к `timed` (`timedclient-qt5` как ориентир) → kind=dbus.
- **Чтение SMS** — чтение `commhistory.db` (sqlite) → kind=script (только чтение).
- **Отправка SMS** — рискованно из bash; см. [[Безопасность]], [[Открытые-вопросы]].
- **Громкость/фонарь/открыть приложение** — dbus/qml.

## Служебные (встроенные) навыки
- **`memory.set(key, value)`** — запись факта в профиль предпочтений
  (`~/.local/share/harbour-glas/profile.json`, см. [[ADR/0006-память-предпочтения]]).
  **Всегда требует подтверждения** в UI: модель не пишет в память молча (защита от
  промпт-инъекций). Не входит в общий каталог навыков для удаления.
- **`memory.forget(key)`** — удаление факта (тоже с подтверждением).
- Доступ на чтение профиля отдельным навыком не нужен: профиль всегда в system-prompt.

## Журнал и undo
- Каждое выполнение пишется в SQLite (`id`, навык, слоты, результат, время).
- `undo` — отдельный скрипт/действие; кнопка «Отменить» на баббле команды.
- Cancel отменяет текущую обработку (kill + прерывание инференса), не путать с undo.

## Раскладка данных
`~/.local/share/harbour-glas/skills/<id>/manifest.json` + скрипты.
Встроенные (built-in) — в `/usr/share/harbour-glas/skills/`.

См. [[Шаблоны-команд]], [[Безопасность]], [[Промпты]].
