# Навыки

> Состояние (2026-10-17): трейт `Skill`, `SkillRegistry` и набор **builtin**-навыков реализованы
> в крейте **`glas-core`** (`set_timer`, `delete_timer`, `delete_alarm`, `set_volume`, `send_sms` —
> фейковые, для host-тестов). **`DeclarativeSkill` ещё нет.** `SkillsPage.qml` — скелет. Решение об
> исполнении — [[ADR-0007-исполнение-навыков]]. Встроенная «память» (`memory.*`) — через
> `Command::MemorySet`/`MemoryForget` (см. [[Контекст-и-память]]).

«Навык» = **объявленное действие**: манифест (`manifest`) + реализация. Пользователь может
включать/выключать и добавлять свои (см. [[Шаблоны-команд]]).

> **Термин:** везде используем **«навык»** (не «команда»). Фраза пользователя — это «запрос»,
> а сущность, которая его исполняет — «навык».

## Главный принцип: декларативно, без произвольного кода

**Никакого исполнения чужого кода.** `sh`/`python3` скрипты из `.gskill`/URL **не запускаем**
(вектор малвари, невалидируемо). Вместо этого — **один трейт `Skill`** и две реализации,
неразличимые для ядра:

```rust
trait Skill {
    fn manifest(&self) -> &Manifest;
    fn validate(&self, params: &Params) -> Result<(), SkillError>;   // дефолт — из манифеста
    fn execute(&self, params: &Params, ctx: &Ctx) -> Result<Outcome, SkillError>; // действие
    fn read(&self, params: &Params, ctx: &Ctx) -> Result<Data, SkillError>;       // опц.: запрос
}
```

- **`BuiltinSkill`** — на Rust, вкомпилирован (таймер, SMS, громкость, фонарь, открыть
  приложение…). Тестируется на хосте, безопасно по построению. Реализуются **через интерфейсы
  ОС**, не через железо — см. [[ADR-0010-примитивы-через-ОС]]; полный инвентарь доступного —
  [[Возможности-ОС]].
- **`DeclarativeSkill`** — собирается **из манифеста** и выполняет один примитив:
  `dbus`-вызов / `open`-URI / **композицию** builtin'ов. Кода нет — только данные.

**`read` — не отдельная сущность, а дополнительный метод навыка** (опционально): `BuiltinSkill` —
Rust-метод, `DeclarativeSkill` — декларативный `read` (dbus-запрос) в манифесте. Возвращает
**данные** (список/значение) для ответа или конкретизации уточняющего вопроса (напр. «удали
будильник» → список будильников). `execute` — действие, `read` — запрос. См.
[[ADR-0012-диалог-контекст-выход-чтение]].

Навык, создающий объект, может вернуть в результате **`id` от ОС** (напр. cookie таймера); ядро
пишет его в строку контекста, чтобы следующие ходы разрешали ссылки («удали его»). Это **не память
объектов** — см. [[Контекст-и-память]].

Одни и те же данные (`manifest`) питают **три** вещи: каталог интентов для промпта,
валидацию слотов и исполнение.

## Манифест (декларативный)

```json
{
  "schema": 1,
  "id": "set_timer",
  "name": "Таймер",
  "description": "Поставить таймер на N минут",
  "examples": ["поставь таймер на 5 минут", "таймер 10 мин"],
  "params": {
    "duration_seconds": { "type": "int", "required": true, "min": 1 }
  },
  "do": [
    { "dbus": { "bus": "session", "dest": "com.nokia.time", "path": "/", "iface": "…", "method": "…", "params": { "seconds": "%duration_seconds" } } }
  ],
  "undo": [ { "dbus": { "…": "…" } } ],
  "danger": false
}
```

- **`do`** — список примитивов (композиция): `dbus` / `open` / `builtin`. Позволяет собирать
  рецепты из готовых действий без кода.
- **`%name`** — подстановка слота **в данные** (`dbus`-аргумент, URL), не в shell-строку.
- **`undo`** — обратная композиция (кнопка «Отменить»).
- **`danger`** — декларативный флаг подтверждения (см. [[Безопасность]]).

## Валидация слотов

- Типы из `params` (`int`, `float`, `bool`, `enum`, `string`), диапазоны, обязательность.
- **Не хватает обязательных данных → ассистент доспрашивает** (уточняющий вопрос от модели), а не
  отказывает. См. [[#Дозапрос данных (slot-filling)]] и [[ADR-0011-сессия-и-подтверждение]].
- Неизвестный интент → «не понял»; выключенный/несуществующий навык → сообщаем «такого навыка нет /
  он выключен».
- Валидация **декларативная** и не зависит от «языка исполнения» (произвольного кода нет).

## Дозапрос данных (slot-filling)

- **Манифест — контракт не только для ядра, но и для модели.** `params` (имена/типы/обязательность)
  уходят в промпт: модель предупреждена, что для запуска навыка нужны **все обязательные** данные.
- Если в реплике данных не хватает — **модель формулирует уточняющий вопрос** («На сколько минут?»),
  а не отказывает. Ответ пользователя продолжает **ту же сессию** (см. ниже).
- Если навык умеет **читать** кандидатов (`read`-метод), вопрос **конкретизируется списком**
  («У тебя 3 будильника: 7:00, 8:00, 9:00. Какой удалить?»), иначе — общий.
- Частично заполненный вызов — состояние сессии; заполнили всё → исполняем.
- См. [[Промпты]], [[ADR-0011-сессия-и-подтверждение]], [[ADR-0012-диалог-контекст-выход-чтение]].

## Реестр навыков (`SkillRegistry`) — единый источник правды

```
~\ .local/share/harbour-glas/skills/<id>/manifest.json (+ ассеты)   ← пользовательские
/usr/share/harbour-glas/skills/<id>/manifest.json                   ← builtin (в RPM)
```

- Реестр при старте (и при изменении) сканирует обе папки, парсит каждый `manifest.json`,
  строит индекс по `id`. Бэд-запись пропускается с понятным сообщением — реестр не падает.
- **Вкл/выкл** — список отключённых `id` в настройках (файлы не удаляем).

## Источники навыков (добавление без правки кода)

| Источник | Как | Куда |
|---|---|---|
| builtin | в RPM | `/usr/share/harbour-glas/skills/` (read-only) |
| пользовательские | «+» → выбрать папку | `~/.local/share/harbour-glas/skills/` |
| скачанный файл | «+» → выбрать `.gskill` | распаковка в пользовательскую папку |
| по URL | «+» → ссылка → скачать → проверка `sha256` → **ревью-диалог** → установить | туда же |

## Примеры для MVP (builtin)

- **Таймер/будильник** — D-Bus к `timed` (`timedclient-qt5` как ориентир).
- **Чтение SMS** — `commhistory.db` (sqlite; `python3-sqlite` есть по умолчанию) — builtin
  (не пользовательский скрипт!).
- **Громкость/фонарь/открыть приложение** — dbus / open.
- **Отправка SMS** — отдельно и осторожно, `danger` (см. [[Безопасность]], [[Открытые-вопросы]]).

## Служебные (встроенные) навыки

- **`memory.set(key, value)`** — запись факта в профиль (`~/.local/share/harbour-glas/profile.json`,
  см. [[ADR-0006-память-предпочтения]]). Всегда требует подтверждения в UI (защита от
  промпт-инъекций). Нельзя удалить из каталога.
- **`memory.forget(key)`** — удаление факта (тоже с подтверждением).
- Чтение профиля отдельным навыком не нужно: профиль всегда в system-prompt.

> Реализовано (2026-10-17): запись/удаление профиля идут через `Command::MemorySet`/`MemoryForget`
> (UI/подтверждение), а не через навык `memory.*`. Навыки `memory.set`/`memory.forget` — впереди.

## Сессия и состояние навыка

- Многошаговый ход (подтверждение, уточнение) держит **сессию** (`SessionId`); ядро маршрутизирует
  следующую реплику **тому же навыку** по индексу `session_id → skill_id`. См.
  [[ADR/0011-сессия-и-подтверждение]].
- Навык может хранить **состояние сессии** (напр. курсор чтения списка). Оно чистится по
  `SessionEnded` и при сбросе (потеря связи/отмена) — новый ход начинается с чистого листа.
  > Реализовано (2026-10-17): состояние сессии пока держит **ядро** (`dialog.rs`), а не сам навык
  > (эквивалентно по поведению; навык стателесс). Состояние в навыке — впереди.
- Во время `AwaitingConfirmation` ввод **сужен** до ответа «да/нет»; реплика, **не являющаяся
  ответом**, выводит в **новый навык** (см. [[Безопасность]], [[ADR-0012-диалог-контекст-выход-чтение]]).
- **Выключенный навык не исполняется**, даже если его интент всё-таки пришёл: список отключённых —
  единый источник и для промпта (Q-5), и для исполнения.
- **Перебивание:** повторное нажатие PTT во время обработки/озвучки прерывает текущее и начинает
  новую запись; это не «отмена» действия (undo), а прерывание хода. См.
  [[ADR-0012-диалог-контекст-выход-чтение]].

## Журнал и undo

- Каждое выполнение пишется в SQLite (`id`, навык, слоты, результат, время).
- `undo` — обратная композиция; кнопка «Отменить» на баббле команды.
- **Cancel** отменяет текущую обработку (прерывание инференса), не путать с undo. Тот же эффект —
  **повторное нажатие PTT** (перебивание). См. [[ADR-0012-диалог-контекст-выход-чтение]].
