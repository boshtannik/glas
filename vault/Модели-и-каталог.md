# Модели и каталог

> Состояние: сверено с кодом 2026-10-15.

## Роли моделей
- **asr** — распознавание речи: whisper.cpp `ggml-*.bin` (через `whisper-cli`).
- **tts** — синтез: piper `*.onnx` + `*.onnx.json`.
- **llm** («thinking») — извлечение интентов: GGUF (инференс на candle, см. [[Архитектура]]).

## Два независимых каталога
1. **STT/TTS** (`voice.rs`, `VoiceModelsPage`) — общий с harbour-opencode:
   `catalog.json` в общем store, скачивание через `curl`, выбор в `voice_state.json`.
2. **LLM/thinking** (`llm.rs`, `ThinkingModelsPage`) — **живой Hugging Face API**,
   собственный кэш `llm_catalog.json` (+ `llm_meta.json` для разрешённых файлов).

Общий store-каталог: `~/.local/share/harbour-opencode/` если он есть, иначе
`~/.local/share/harbour-glas/` (одни и те же модели не качаются дважды).

## Каталог LLM — живой Hugging Face API (реализовано)
Кнопка/PullDown «Update model catalogs» → `llm_catalog_update`. Механика (`llm.rs`):
- **Список и поиск** — серверный запрос
  `huggingface.co/api/models?filter=gguf&filter=text-generation&sort=downloads&direction=-1&limit=30`
  (+ `&search=<query>`, `&cursor=<next>` для пагинации). Курсор берётся из заголовка
  `Link: …; rel="next"`.
- **Отсечение по устройству** без лишних запросов: из имени репозитория парсится число
  параметров (`7b`, `1.5B`, `360M`, MoE `30B-A3B`), и записи сверх
  `max_params_b(MemAvailable)` отбрасываются.
- **Ленивое разрешение файла** — один запрос `GET /api/models/<repo>?blobs=true` только
  при открытии карточки (`ModelCardPage`): выбирается GGUF по предпочтению кванта
  (`q4_k_m → q4_k_s → q4_0 → q5_k_m → q3_k_m → q8_0 → q6_k → q2_k → iq4_xs`, иначе
  самый маленький); пропускаются `mmproj` и шарды `-of-`; URL —
  `huggingface.co/<repo>/resolve/main/<файл>?download=true`. Результат кэшируется в
  `llm_meta.json`.
- **Кэши:** `llm_catalog.json` (список) и `llm_meta.json` (размер/URL/квант по repo),
  отдельно от opencode-каталога STT/TTS.

> ⚠️ Прежняя схема «вшитый курируемый список репозиториев + ручной `tree/main`»
> **заменена** на живой поиск с пагинацией. Ранний dev-сид из общего `catalog.json`
> больше не используется.

## Плашечки влезаемости (бейдж у модели)
Считается в `llm.rs::fit_for`, показывается точкой/текстом в `ThinkingModelsPage` и
`ModelCardPage`. Пока карточка не открыта, размер берётся из оценки по числу
параметров (Q4, `BYTES_PER_PARAM_Q4 ≈ 0.62 ГБ/1B`) и помечается `≈`/`approx`.
- `need ≈ size + size/8 + RUNTIME_OVERHEAD (160 МБ)`.
- `usable = MemAvailable − RAM_RESERVE (512 МБ)` из `/proc/meminfo`.
- 🔴 `need > usable` или `size > свободный диск`; 🟡 `need > usable·0.8`; иначе 🟢.
- **Swap НЕ учитываем** (на Sailfish это zram — реальной ёмкости не добавляет).

Свободные RAM и место на диске показываются в шапке списка и в карточке
(`refresh_device`, обновляются при новых данных, а не на каждом poll).

## Выбор моделей
- Хранится по **одной активной модели на роль** (`voice_state.json`: `stt`/`tts`/`llm`).
- Скачивание с прогрессом, отмена, удаление, выбор — как `VoiceModelsPage`.
- Рекомендуемые для интентов LLM: Qwen2.5 0.5B/1.5B-Instruct, SmolLM2-360M/1.7B,
  Gemma-2-2B (проверить RU-качество и скорость на Snapdragon 695).

## Расположение
`<store>/models/<model_id | repo>/…`, где `<store>` — общий с opencode (см. выше).

## Движки vs модели
- Движки (`whisper-cli`, `piper`) — в RPM (`/usr/libexec/harbour-glas/`).
- Модели — НЕ в RPM; качаются пользователем.
- Упакованный `assets/models.json` сейчас **пустой** (`{"schema":1,"models":[]}`).
