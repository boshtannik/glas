# ADR-0008: Ядро — один worker и единая очередь событий; протокол — исчерпывающие enum + константы

**Статус:** принято · **Дата:** 2026-10-16
**Связано:** [[Архитектура]], [[План]], [[ADR-0009-модельный-слой]]

## Контекст

Сейчас вся логика живёт в QML-потоке: `AppBridge` держит **три отдельных `mpsc`-канала**
(`rx` — STT, `tts_rx` — TTS, `gen_rx` — LLM), у каждого своя ветка в `poll()`, а длительные
операции — ad-hoc `std::thread`. Сквозной пайплайн «хода» (STT → интент → безопасность →
навык → TTS) **не собран**: стадии живут раздельно. При росте числа стадий и событий эта
схема расползается: каждый новый поток = новый канал + новая ветка опроса + новый флаг busy.

## Решение

1. **Единая очередь событий** (`mpsc<Event>`): команды UI, результаты STT/LLM/скачивания,
   таймеры, D-Bus — всё стекается в **один** канал.
2. **Один worker-поток** — event-loop + автомат «хода»; вся диспетчеризация в **одном**
   `match` (как `dispatcher.rs` в opencode). Тяжёлые операции по-прежнему в своих потоках,
   но результат шлют **в общую очередь**, а не в приватный канал.
3. **Автомат хода:**

   ```
   Idle → Recording → Transcribing → Thinking → [AwaitingConfirmation] → Executing → Speaking → Idle
   ```

   - `Thinking` включает сборку промпта (память + каталог интентов) и инференс.
   - `AwaitingConfirmation` — пауза автомата под подтверждение опасного действия (round-trip
     через ту же очередь).
4. **Протокол — исчерпывающие enum'ы + константы** (правила владельца из opencode):
   - `Command` (UI → ядро): `CaptureStart`/`CaptureStop`, `Cancel`, `Confirm`, `MemorySet`/`MemoryForget`, команды model-store, …
   - `Event` (ядро → UI): `Transcribed`, `ModelOutput`, `AnswerReady`, `NeedsConfirmation`, `ActionResult`, `TtsReady`, `Error`, прогресс загрузок, …
   - Без `Unknown`/`_ =>`; на нереализованные ветки — `log::warn!`; имена ключей/маркеров —
     в константах (стиль `types/keys.rs` в opencode), а не сырые строки.
   - Логи — только на английском.

## Почему так

- Вся логика в одном месте → легко добавлять стадии и пересматривать поведение.
- QML — только рисование и отправка команд; один вход и один выход (`poll()` /
  queued-сигнал).
- Исчерпывающие enum'ы дают компиляторскую поддержку при росте union'а событий.
- Устраняет связку «N потоков × N каналов × N веток опроса».

## Последствия

+ Расширяемость пайплайна, единая точка диспетчеризации, компилятор помогает.
+ Тестируемость: автомат и диспетчер — чистая логика (в идеале — отдельный модуль/крейт без Qt).
− Разовый рефактор `AppBridge` (свести три канала и `poll()` к одному worker'у).
