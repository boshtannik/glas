# ADR-0006: Память — скользящее окно + долговечный профиль предпочтений

**Статус:** принято · **Дата:** 2026-10-11

## Контекст
ADR-0003 зафиксировал скользящее окно для диалога. Но окно не хранит пользовательские
предпочтения: как только реплика выпала, ассистент «забыл» имя, язык, формат времени и т.п.
Саммари **всей** истории на устройстве дорого (лишний инференс на каждый перессказ),
лоссово и склонно к накоплению искажений; предпочтения в повествовательном саммари
размываются и иногда теряются.

## Решение
Две независимые памяти:

1. **Диалоговая (working memory)** — скользящее окно, как в [[ADR/0003-контекст-окно]]
   (`max_turns`≈8, `max_tokens`≈700). Дёшево, детерминировано, без инференса.
2. **Профиль предпочтений (долговременная)** — маленькое структурированное хранилище
   фактов (`profile.json`, key→value) с жёстким лимитом ~200–400 токенов, которое
   **вставляется в system-prompt на каждом ходу**. Предпочтения переживают выпадение
   реплики из окна.
3. **Компактификация хвоста (опционально, позже)** — при переполнении окна выпадающие
   старые ходы *один раз* сжимаются в короткую rolling-summary. Это редкий фоновый
   инференс, а не действие на каждый ход.

Правила профиля:
- Запись — только через встроенный скилл `memory.set(key, value)` и **с подтверждением
  пользователя** в UI (защита от промпт-инъекций: модель не пишет в память молча).
- Отдельная страница «Память»: просмотр, правка и удаление фактов (прозрачность и приватность).
- Предпочтения **никогда не суммаризуются**; диалоговая память не смешивается с профилем.

## Схема профиля (черновик)
```json
{
  "schema": 1,
  "facts": {
    "name": { "value": "Джек", "updated": 1760000000, "source": "user" },
    "language": { "value": "ru", "updated": 1760000000, "source": "user" },
    "time_format": { "value": "24h", "updated": 1760000000, "source": "model" },
    "tts_voice": { "value": "irina", "updated": 1760000000, "source": "user" }
  }
}
```
- В промпт уходит плоский список: `Known user preferences: name=Джек; language=ru; time_format=24h; …`
- Лимит: не более N фактов / ~400 токенов; при превышении — отказ записи + подсказка пользователю.

## Как наполняется
- Пользователь прямо просит («запомни, что…») → `memory.set` с подтверждением.
- Модель замечает устойчивое предпочтение → **предлагает** сохранить (кнопка в баббле),
  не пишет сама.
- Настройки приложения (язык, голос, формат времени) — тоже могут зеркалиться в профиль.

## Последствия
+ Предпочтения переживают выпадение из окна → ассистент «узнаёт» пользователя.
+ Предсказуемый и малый прирост к промпту (профиль ≤ ~400 токенов).
+ Прозрачность и контроль: пользователь видит и правит память.
− Нужны: скилл записи + подтверждение + страница «Память».
− Две подсистемы вместо одной (усложнение).
− Без компактификации далёкие отсылки всё ещё теряются (принято, см. ADR-0003).
