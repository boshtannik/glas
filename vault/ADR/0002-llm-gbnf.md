# ADR-0002: Извлечение интентов — llama.cpp (GGUF) + GBNF

**Статус:** принято · **Дата:** 2026-10-11

## Контекст
Нужен локальный, on-device маппинг «фраза → готовая команда». Модель должна быть
маленькой и «глупой», без рассуждений.

## Решение
- Инференс через llama.cpp (Rust-обвязка), модель в GGUF.
- Вывод ограничен **GBNF-грамматикой** строго под `{intent, params, reply}|unknown`.
- Низкая temperature, минимальное `n_ctx`.
- Валидация слотов повторяется в `skills`.

## Последствия
+ Никаких «выдуманных» интентов/битого JSON — грамматика гарантирует форму.
+ Полностью offline.
− Нужно подобрать модель/квант под Snapdragon 695; следить за RAM (см. [[Автономность]]).

## Обновление (2026-10-15): отказ от llama.cpp в пользу candle

**Что изменилось в части «инференс»:**
- Сборка llama.cpp из исходников под sb2 (CMake) **зависала** и была отброшена.
- Инференс переведён на **`candle` (чистый Rust)** — работает на устройстве
  (`glas/src/infer.rs`, диспатч по `general.architecture`). Подробности — `session-memory.md`
  за 2026-10-15. **Эта часть решения заменена, GBNF-часть пересматривается.**
- Целевой формат вывода — прежний: `{intent, params, reply} | unknown`, низкая temperature,
  повторная валидация слотов в `skills`.

**Открытый вопрос:** у candle **нет GBNF**. Нужно выбрать механизм гарантии формы JSON:
1. **Промпт + строгий парсер + retry** (проще; гарантии нет, но на «глупых» моделях + валидации часто хватает).
2. **Ручная constrained-decoding**: на каждом шаге маскировать логиты по маленькому
   автомату JSON/схемы (маска по id токенов из GGUF-словаря). Гарантия как у GBNF, но объём кода.
3. **`llguidance`** (крейт-грамма-движок) поверх candle — гарантия, но интеграция нетривиальна.

Решение по пункту выше пока **не принято** (см. [[Открытые-вопросы]]).
